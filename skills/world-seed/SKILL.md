# world-seed：把“她生活的世界”整理成可导入的种子

你在帮用户写一份 AstrBot 插件（影忆 ShadowMemory）可以直接导入的**世界种子**。产物是一个 JSON 文件（`world_seed/v1`），不是给人读的散文。

导入方式（告诉用户即可，不需要你执行）：

1. 把 JSON 保存成 `world_seed.json`；
2. 在故事页导入这份种子，或按插件文档放到种子目录后导入；
3. 没有种子时故事模块不会启动。导入后下一场才用这份新种子，已经演过的场景不会被改写。

这个技能**不创建配角**。人物只写成种子条目。要让某人单独扮演，是故事开演以后由背景模型提名的事。

## 工作流程

1. **听**：让用户用他自己的话讲这个世界——她在哪生活、日子大概什么样、什么绝对不能发生。不要急着写 JSON。
2. **问基调**：一次问 2–3 个会改变产出的问题。例如这是不是真实世界、她日常待在哪些地方、有没有不能破的规矩。
3. **对照**：如果用户贴了人格种子或事实，世界不得与之矛盾。矛盾就改世界，不要改她。
4. **写**：按下面的规则写 JSON，并按 `references/schema.md` 自检。
5. **交**：只输出一个 JSON 代码块，不要解释。

## 可以补、不可以编

- 可以补日常细节：天气怎么被她感知、街道大概的安静程度、一天的起居节奏。这些是为了让大纲和条目够具体。
- 不编人物关系、承诺和规矩。用户没说的人与人之间的事、欠下的承诺、世界规则，都不要补。
- 用户明确否定的不写。
- 不确定就留空，或再问一句。宁可条目少，不要写成另一部小说。

## 硬规则

- `outline` 50 到 3000 字，写她生活的世界，不写剧情结局。
- `entries` 里每条有类别、名字、正文。类别用：人物、地点、组织、规则、物品、其他。
- 人物条目是龙套或将来可以晋升的名字，不要在这里写人格三层。
- `hooks` 最多 10 条，每条不超过 200 字，是还没发生的钩子，不是已经演完的情节。
- `opening` 只有地点和她在做什么，给第一场用。
- 整个 JSON 能被 `json.loads` 解析；没有注释、没有尾逗号。

## 输出格式

```json
{
  "version": "world_seed/v1",
  "title": "青屿",
  "outline": "她是青屿大学的学生，住在学校北门外的合租屋。日子按课表和打工转，风大的时候海就在耳边，不发生奇迹。",
  "entries": [
    {"category": "地点", "name": "合租屋", "body": "北门外一栋旧居民楼的两室，厨房小，晚上能听见楼下车。"}
  ],
  "hooks": ["期末前要交一份小组报告"],
  "opening": {"where": "合租屋", "doing": "赖床"}
}
```

字段约束见 `references/schema.md`，一份更完整的例子见 `examples.md`。
